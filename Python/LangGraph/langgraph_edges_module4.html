LangGraph Module 4 — Edges: an interactive visual guide covering Simple Edges, Conditional Edges, Dynamic Routing, Branching, Multiple Paths, and Edge Logic

A simple edge is a fixed, unconditional connection from one node to the next. Every time node A finishes, execution always moves to node B — no conditions, no decisions.

Regular node
START / END
Simple edge
# add_edge(from_node, to_node) — unconditional builder.set_entry_point("clean_node") builder.add_edge("clean_node", "count_node") builder.add_edge("count_node", "validate_node") builder.add_edge("validate_node", END)

set_entry_point() is a shorthand for add_edge(START, "first_node")

A conditional edge runs a router function after a node finishes. The router reads the state and returns a string that names the next node. LangGraph jumps to that node.

Regular node
Router function
START / END
def route_after_validate(state): if state["is_valid"]: return "publish" # string must match a node name return "reject" builder.add_conditional_edges( "validate_node", # source node route_after_validate, # router function { # mapping: return value → node name "publish": "publish_node", "reject": "reject_node", } )

The router function must return one of the keys in the mapping dict. LangGraph raises an error if the return value is not a known key.

Dynamic routing means the router function decides the path at runtime — based on live state values, not hard-coded logic. The set of possible destinations is declared upfront, but which one is chosen depends entirely on what is in the state when the node finishes.

Processing node
Dynamic router
Destination node
def route_by_type(state): doc_type = state["doc_type"] # read from live state if doc_type in ["pdf", "email", "contract"]: return doc_type # dynamic — could be any of the three return "email" # safe fallback builder.add_conditional_edges( "classify_node", route_by_type, { "pdf": "pdf_handler", "email": "email_handler", "contract": "contract_handler", } )

Always include a fallback return in your router so unknown values don't crash the graph.

Branching sends execution down one path chosen from several options. Unlike fan-out (parallel), branching picks exactly one branch. The branches recombine at a shared downstream node.

Start / join node
Router
Branch node
def route_by_urgency(state): score = state["urgency_score"] if score >= 9: return "fast" if score >= 5: return "std" return "deep" builder.add_conditional_edges( "triage_node", route_by_urgency, {"fast": "fast_path", "std": "standard_path", "deep": "deep_path"} ) # all branches converge at respond_node builder.add_edge("fast_path", "respond_node") builder.add_edge("standard_path", "respond_node") builder.add_edge("deep_path", "respond_node")

Fan-out means one node triggers multiple downstream nodes that run in parallel. LangGraph supports this by adding several edges from a single source. All parallel branches must finish before execution continues at the join node.

Source / join node
Parallel branch
# Fan-out: add multiple edges from one source builder.add_edge("ingest_node", "chunk_node") builder.add_edge("ingest_node", "metadata_node") builder.add_edge("ingest_node", "detect_lang_node") # Fan-in: all branches connect to the same join node builder.add_edge("chunk_node", "embed_node") builder.add_edge("metadata_node", "embed_node") builder.add_edge("detect_lang_node", "embed_node") # embed_node runs only after ALL three branches finish

LangGraph waits for all incoming edges to complete before running the join node. Use reducers (from Module 2) to merge concurrent state updates correctly.

Edge logic covers loops (routing back to an earlier node), cycle detection, and how to implement retry or self-correction patterns cleanly.

Processing node
Router (decides loop or exit)

def check_quality(state): if state["quality_score"] >= 0.8: return "pass" if state["retries"] >= 3: return "max_retries" # exit loop safely return "retry" # loop back builder.add_conditional_edges( "llm_node", check_quality, { "pass": END, "retry": "llm_node", # points back to same node! "max_retries": "fallback_node", } ) # llm_node must also increment retries def llm_node(state): response = call_llm(state["prompt"]) score = evaluate(response) return { "response": response, "quality_score": score, "retries": state["retries"] + 1 }

Always guard loops with a max-retry counter. Without it, a consistently failing node loops forever and the graph never terminates.
